Reading Note

Towards a General Recipe for Combinatorial Optimization with Multi-Filter GNNs

F. Wenkel, S. Cantürk, S. Horoi, M. Perlmutter, G. Wolf · 2024 · Link to paper

Finished Started Apr 2026

Why I read this

As part of my master's program at the African Institute for Mathematical Sciences (AIMS), Rwanda, I completed an eight-week research thesis on learning-based approaches to combinatorial optimization. This paper was the central reference for my work. I aimed to reproduce the authors' experimental results and explore the generality of their framework by applying it to new optimization problems and formulations.

What the paper does

The authors introduce the Graph Combinatorial Optimization Network (GCON), a graph neural network architecture designed specifically for graph-based combinatorial optimization problems. With a lot of graph based combinatorial optimization problems being NP-hard or NP-complete and exact solutions being out of reach, the GCON is proposed as a learned solver The key idea behind GCON is to incorporate structural information from graphs through a multi-filter architecture inspired by Graph Signal Processing. Instead of relying on a single aggregation operation, GCON uses a bank of graph filters to capture different aspects of the graph structure and learn more expressive node representations using attention mechanisms.

The network is trained in a self-supervised manner, with problem-specific loss functions encoding the constraints rather than requiring labelled optimal solutions. The continuous outputs produced by the network are then converted into feasible discrete solutions through problem-specific decoding procedures. In this way, the framework provides a general approach for applying graph neural networks to different combinatorial optimization tasks.

Main ideas

The paper proposes GCON (Graph Combinatorial Optimization Network), a neural network architecture built for combinatorial optimization problems on graphs. In particular the authors use only finite, connected graphs in their work. It builds on the ScatteringClique architecture introduced by Min et al., keeping its multi-filter design which was inspired by concepts in Graph Signal Processing (GSP), but replacing how the filters are combined. Instead of a single attention vector across both filter classes, GCON uses separate attention vectors for the different filter classes.

The filter bank consists of two filter classes: aggregation filters and comparison filters. A filter can be viewed as a function that transforms the information stored at each node based on the structure of the graph. Since the filters must aggregate and compare information across neighbouring vertices, the network first defines a propagation matrix describing how information is passed through the graph. The propagation matrix used in the paper is \[P = \frac{1}{2}(I + AD^{-1}),\] where \(A\) denotes the adjacency matrix, \(D\) the degree matrix, and \(I\) the identity matrix. This matrix is the transition matrix of the Markov chain defined by the graph being used in the combinatorial optimization problem.

This Markov chain has desirable convergence properties, which provide the theoretical motivation for using separate attention mechanisms for aggregation and comparison filters. In particular, it is both irreducible, meaning that a path exists from every vertex to every other vertex, as well as aperiodic, meaning that the chain does not get trapped in cycles of a fixed length. Therefore, the Markov chain, being finite, is ergodic and the repeated application of the transition matrix converges to a unique stationary distribution, which is the normalized degree vector \(\displaystyle\frac{d}{\|d\|_1}\).

The aggregation filters in GCON's filter bank let the network collect and combine similar information from neighboring vertices, capturing local patterns in the graph's structure. The aggregation filters are defined as \[f_{A}^{k}(X):= P^kX,\] where \(X\) is the matrix containing the features at each node.
But for many combinatorial optimization problems, that's not enough on its own. Take Maximum Independent Set (MIS): a valid solution needs vertices that aren't adjacent to each other. Knowing which neighboring vertices look similar doesn't tell you which ones to avoid selecting together. This is where comparison filters come in. They extract information about how adjacent vertices differ, not just how they're alike. They are defined as \[f_{C}^{k_1,k_2}(X):= (P^{k_1}-P^{k_2})X\] That gives the network a second, complementary signal, one that captures contrast rather than similarity, which turns out to matter for solving these problems well.

Two attention vectors exist in each layer of the GCON, one for each filter class and both of them are learned vectors. These attention vectors are used to compute normalized attention scores, which is essentially a weight given to each of the filter responses, in some filter bank, at some node in the graph. Still keeping the responses across the different filter banks separate, the filter responses at some node are then weighted according to the normalized attention score for that filter at that node and then summed up to get the filter response in some class, at that node. The fact that the attention vectors are learned means that we are essentially learning the importance of each filter at each node thereby extracting the most useful information at each node.

This choice of separating the attention classes is shown to have a theoretical backing.
